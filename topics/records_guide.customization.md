## Custom segments

### What a script may do

Scripts cannot create a custom segment. They can add values to a segment that already exists, and
they can set a segment's field on records. Before scripts can work with a segment this way, the
segment needs at least one value.

### Segment values

Every value of a segment is an instance of a custom record. The record type ID that those value
records use is the ID shown on the segment's definition record.

To look up a value's internal ID, open the segment definition and read the ID column of its Values
sublist. On records that carry the segment, its values show up in a list or multi-select field.
When a script sets a segment field, it may pass either the value's text label or its internal ID.

### Which field ID to use

There are two kinds of ID for a segment field:

- the **legacy field ID**, which is different on each record type the segment applies to (for a
  transaction body field it might look like `custbody_cseg_profitcenter`), and
- the **unified script ID**, which is the same on every record type.

If the "use as field ID" box on the segment definition is checked, the unified script ID is the one
in force. In either case, do not use the definition's own script ID or record ID as the field ID:
those identify the segment definition, not the field on the record.

Because legacy IDs change from one record type to the next, the dependable way to find one is to
open a record of that type in the UI and click the segment field's label, which reveals its ID.

## Custom lists

A custom list provides a predefined set of choices for custom fields. You manage lists in the UI
under Customization > Lists, Records, & Fields > Lists.

Custom list IDs carry the prefix `customlist`, and IDs generated by the system end in a number.

> [!SOURCE-ERROR] The source's note on custom list IDs refers to a custom record type instead of a
> custom list, as though it had been copied from the custom record page. Rely on the `customlist`
> prefix and confirm the ID on the list's own definition.
<!-- source-error: topic:records_guide.customization | - | id_note_says_custom_record_type -->

Scripting support is limited to searching: the only operation available on a custom list is
search, from both client and server scripts. Creating, loading, updating or deleting a list is not
among the supported operations.

| Use | Field IDs |
|---|---|
| Search filters | `internalid`, `internalidnumber`, `isinactive`, `name` |
| Search columns | `internalid`, `isinactive`, `name` |

## Example

A user event script that fills in an empty profit-center segment on new sales orders. The field ID
is the legacy-style example ID from the source; your account's ID may differ. The value is set by
its text label, which segment fields accept as well as the internal ID.

```js
/**
 * @NApiVersion 2.1
 * @NScriptType UserEventScript
 */
define(['N/log'], (log) => {
  const SEGMENT_FIELD = 'custbody_cseg_profitcenter';

  const beforeSubmit = (context) => {
    if (context.type !== context.UserEventType.CREATE) {
      return;
    }
    const order = context.newRecord;
    if (order.getValue({ fieldId: SEGMENT_FIELD })) {
      return;
    }
    order.setText({ fieldId: SEGMENT_FIELD, text: 'Wholesale - West' });
    log.audit({
      title: 'Profit center defaulted',
      details: `Customer ${order.getValue({ fieldId: 'entity' })}`
    });
  };

  return { beforeSubmit };
});
```
